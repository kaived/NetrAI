This document is the single source of truth for RetinaScan AI model progress, current serving status, dataset usage, and next ML steps. It replaces the earlier separate model milestone and model stability notes.

```text
Task: Diabetic retinopathy screening

Current version: aptos-baseline-v1
```

MATLAB is used for model development, training, evaluation, and ONNX export. Production inference does not require MATLAB. The deployed backend loads the exported ONNX file and runs inference through ONNX Runtime.

## What Is Working Now

Backend serving:

```text
POST /predict
GET  /cases/{case_id}
GET  /cases/{case_id}/eyes/{eye}/input
GET  /cases/{case_id}/eyes/{eye}/heatmap
```

The backend currently supports:

1. Image upload as multipart form data.
2. Case ID generated by frontend or backend fallback.
3. OD/OS eye-specific screening under the same case.
4. Quality gate before model inference.
5. ONNX inference.
6. Confidence-level classification: low, moderate, high.
7. Eye-specific heatmap artifacts.
8. Firestore case metadata.
9. GCS input/output artifact storage in production.
10. Final two-eye report after both OD and OS are completed.

Frontend workflow:

```text
New Screening
  -> generate one Case ID
  -> analyze OD
  -> OD disabled
  -> OS auto-selected
  -> analyze OS
  -> final two-eye clinical report shown
```

No browser storage is used. Refresh recovery uses the `case_id` URL parameter and backend case restore.

## What We Are Working On Now

Current active model work:

3. Reduce false negatives for referable DR.

## Current Limitations

The current model is demo-grade, not clinical-grade.

Known limitations:

1. The model was trained on APTOS only.
2. Severe and proliferative DR recall need improvement.
3. The attention map is a computer-vision lesion-attention heatmap, not true model-layer Grad-CAM yet.
4. No external validation has been completed on Messidor-2 or IDRiD.
5. No calibrated confidence threshold has been formally selected yet.
6. No lesion-level segmentation model is connected to production yet.

## Dataset Roles

Do not merge every dataset into training immediately. Use each dataset for a clear purpose.

| Dataset | Purpose | When To Use |
|---|---|---|
| APTOS 2019 | Main DR classifier training | Current baseline and stable v2 training |
| Messidor-2 | External validation | After APTOS v2 is trained, to prove generalization |
| IDRiD | India-context validation and lesion masks | Validate classifier and later train lesion/explainability modules |
| DRIVE | Vessel segmentation only | Future vessel-quality and vascular-structure features, not DR grade training |

Dataset strategy:

```text
Train on APTOS first
  -> validate internally on fixed APTOS split
  -> validate externally on Messidor-2
  -> validate India-context behavior on IDRiD
  -> use IDRiD masks for lesion-level explainability
  -> use DRIVE for vessel segmentation experiments only
```

## Acceptance Criteria

Use screening-first metrics. In diabetic retinopathy screening, missing referable disease is worse than sending one extra referral.

Stable v2 should be accepted if it improves most of these:

```text
referable_dr_sensitivity >= 0.92
referable_dr_specificity >= 0.88
false_negative <= baseline false_negative
severe recall improves
proliferative_dr recall improves
macro_f1 improves
quadratic_weighted_kappa improves
```

If severe/proliferative recall improves but total accuracy drops slightly, the model may still be better for screening.

## Next Plan With Other Datasets

Messidor-2:

1. Build a Messidor-2 index.
2. Map labels into the same 0-4 or referable/non-referable target.
3. Run inference using the trained APTOS model.
4. Report external referable DR sensitivity and specificity.
5. Use this as proof that the model generalizes beyond APTOS.

IDRiD:

1. Build an IDRiD image index.
2. Map image-level labels into the same grading scheme where possible.
3. Validate classifier performance on Indian retinal images.
4. Use lesion masks later for microaneurysm, hemorrhage, exudate, and soft-exudate explainability.
5. Use IDRiD as the next step toward clinically meaningful heatmaps.

DRIVE:

1. Keep DRIVE separate from DR grade training.
2. Use it for vessel segmentation experiments.
3. Later use vessel quality/visibility as an image-quality feature.
4. Do not use DRIVE to claim DR grading performance.
